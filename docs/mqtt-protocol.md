# Протокол общения устройства с сервером (MQTT)

Версия 1.0 — фиксируем и не меняем без согласования.

## Общая схема

```
ESP32 (на машине)  --MQTT-->  Mosquitto (брокер)  -->  CaspX backend  -->  БД / фронтенд
```

- Брокер: **Mosquitto**, порт **1883**, без TLS (для MVP).
- Протокол: **MQTT 3.1.1**, QoS **1** (гарантированная доставка, но без дублей ровно один раз не гарантируется — сервер умеет переживать повторы).
- Частота отправки: **каждые 3–5 секунд** в движении. Можно реже (10 с) в простое.

## Устройство получает при создании (через `POST /devices`)

| Параметр | Пример | Назначение |
|---|---|---|
| `deviceKey` | `dev_a1b2c3d4` | Публичный ID устройства. Используется в имени топика |
| `apiKey` | `sk_casp_8f2e...` | Секретный ключ. Шлётся в теле сообщения. Показывается один раз! |

`apiKey` нужно прошить в ESP32. Если он потерян — создайте устройство заново.

## Топик

```
casp/telemetry/{deviceKey}
```

Пример: `casp/telemetry/dev_a1b2c3d4`

## Формат сообщения (JSON)

```json
{
  "apiKey": "sk_casp_...",
  "lat": 43.6507,
  "lng": 51.167,
  "speedKmh": 62.4,
  "temperature": 27.3,
  "humidity": 34.0,
  "tilt": 3.2,
  "doorOpen": false,
  "batteryPct": 88,
  "photoUrl": null,
  "ts": 1724060000000
}
```

| Поле | Тип | Обязательное | Пояснение |
|---|---|---|---|
| `apiKey` | string | да | Секретный ключ устройства |
| `lat`, `lng` | number | да | Координаты (WGS84, десятичные градусы) |
| `speedKmh` | number | нет | Скорость, км/ч |
| `temperature` | number | нет | Температура, °C |
| `humidity` | number | нет | Влажность, % |
| `tilt` | number | нет | Наклон, градусы (по модулю) |
| `doorOpen` | boolean | нет | Дверь грузового отсека открыта/закрыта |
| `batteryPct` | number | нет | Заряд батареи, % |
| `photoUrl` | string | нет | Ссылка на фотографию (см. раздел «Фото») |
| `ts` | number | нет | Время в миллисекундах (epoch ms). Если нет — сервер берёт своё |

## Пограничные случаи

- Нет GPS-сигнала → **не отправлять** сообщение (или слать с флагом-заглушкой нельзя; лучше ждать фикс).
- `temperature`/`humidity`/`tilt`/`doorOpen` недоступны на устройстве → просто не включать их в JSON.
- `lat`/`lng` — всегда обязательные: если их нет, сообщение отклоняется.

## Алерты, которые сервер строит сам (прошивка НЕ должна ничего считать)

- Температура выше `ALERT_TEMP_MAX` (по умолчанию **30°C**) → `TEMPERATURE_HIGH`
- Температура ниже `ALERT_TEMP_MIN` (по умолчанию **2°C**) → `TEMPERATURE_LOW`
- Влажность вне диапазона 10–95% → `HUMIDITY_HIGH` / `HUMIDITY_LOW`
- Наклон > 30° → `TILT`
- `doorOpen = true` → `DOOR_OPEN`

## Фото

Видео/фото по MQTT не передаём (тяжело). Схема:
1. ESP32-CAM делает фото и **загружает файл по HTTP** (позже добавим эндпоинт загрузки для устройства).
2. В MQTT-сообщении шлём `photoUrl` — публичную ссылку на загруженное фото.
3. Сервер показывает фото в карточке машины/заказа.

## Что сервер возвращает устройству

Ничего. Телеметрия — «односторонняя» (fire-and-forget). Команды устройству (топик `casp/cmd/{deviceKey}`) добавим отдельным этапом.

## Как проверить связь без прошивки

Любой MQTT-клиент (например `mosquitto_pub`) на ту же тему:

```bash
mosquitto_pub -h <host> -p 1883 -t 'casp/telemetry/dev_a1b2c3d4' \
  -m '{"apiKey":"sk_casp_...","lat":43.6507,"lng":51.167,"speedKmh":62.4,"temperature":27.3,"doorOpen":false}'
```
